# 视觉风格方向（v0.1 草案，待评审）

本轮只定**美术风格方向**：参考依据、基本约束、推荐方案与不推荐方案。不含页面实现、组件规格与完整设计系统；token 值、组件样式细节留到方向确认后单独成文。

评审人是本仓库的作者（中文语境），因此本文用中文写，是本仓库继根 `AGENTS.md` 与 README 之后的第三份中文文档 —— 例外的理由记在 [docs/AGENTS.md](AGENTS.md#writing-rules)。

## 前提约束（先于一切风格选择）

| 约束 | 来源 | 对风格的影响 |
|---|---|---|
| Windows 11 桌面应用，Tauri v2 + React 19 + Vite + Tailwind v4 | [DESIGN.md](../DESIGN.md) §7 | 不能靠浏览器新特性；WebView2 即 Chromium 最新稳定版 |
| UI 文案为中文 | [ui.md](ui.md#copy-and-notifications) | **字体必须用系统字体栈**：打包 CJK webfont 体积 5–20 MB，且与「纯本机、无网络」矛盾 |
| 单窗口、信息密度高（应用列表 / 逐条进度日志 / 清理路径清单 / 历史 / 设置表单） | [ui.md](ui.md) | 风格必须能承载表格与长清单，不能只会做 hero |
| 离线、无遥测、证据驱动、文案克制 | [AGENTS.md](../AGENTS.md)、[docs/AGENTS.md](AGENTS.md) | 「安静、精确、可核对」是产品性格，装饰性风格与其冲突 |
| 中文正文 14px 基线，跟随系统明暗，尊重系统强调色，需全键盘操作（作者已确认） | 本文 §已确认约束 | 两套模式同源、强调色需对比度修正层、焦点环是一等视觉元素 |
| 实现者是单人 + agent，没有专职设计师 | 项目现状 | 风格必须**规则化、可判定**（栅格、细线、单一强调色），不能依赖手绘功力 |
| 已有 token 落点：Tailwind v4 `@theme` 与 `src/styles/` 的状态色 | [src/styles/README.md](../src/styles/README.md) | 方向必须能表达为 CSS 自定义属性 |

### 1. muzimu217/ui-design-agent-kit

可观察证据：README（中文）自述「从口语需求到可验证界面的项目级 AI 设计工作流」；仓库含 `docs/`（14 篇）、`evals/`、`showcase/`、`tooling/sources.lock.json`、`npm run verify` 门禁；`showcase/DESIGN.md` 记录 ink `#111313`、paper `#f2f0e9`、lime `#d4ff3f`、coral `#ff795d`、blue `#74a9ff`、amber `#ffbf69`，字体 Syne / Manrope / DM Mono；`showcase/products/screenshots/readme-desktop.webp` 是真实桌面截图：暖白底、超大字重黑标题、细边框卡片网格、绿色主按钮。

|---|---|
| 视觉风格关键词 | 编辑式展厅（纸底 + 粗黑标题 + 细线卡片）；**仓库本身不是风格库** |

| 间距/圆角/阴影 | 8 卡等宽网格、中等圆角、几乎无阴影（截图观察） |
| 组件风格 | 按钮/卡片/媒体块；偏营销页 |
| 布局方式 | sticky 黑顶栏 + 分栏 hero + 密集面板网格 |
| 图标与插画 | 线性图标 + 文字标签；含 mp4/Remotion 视频管线 |

| 适配成本 | 低（只取理念与版式气质） |

**结论：可作为局部参考**（工作流与「证据截图」方法、以及文档页的编辑式气质），**不可作为颜色、字体或代码来源**。

### 3. google-labs-code/design.md

可观察证据：README 自述「A format specification for describing a visual identity to coding agents」；`docs/spec.md` 定义 YAML front matter 令牌组 `colors` / `typography`(fontFamily、fontSize、fontWeight、lineHeight、letterSpacing、fontFeature、fontVariation) / `rounded` / `spacing` / `components`（支持 `{colors.primary}` 之类令牌引用）；散文段落固定顺序 Overview → Colors → Typography → Layout → Elevation & Depth → Shapes → Components → Do's and Don'ts；CLI `npx @google/design.md lint` 输出含 **WCAG 对比度**检查的结构化 JSON，`diff` 做令牌与散文回归；`examples/` 三个样品（atmospheric-glass、paws-and-paths、totality-festival），其中 Heritage 样品写着「Architectural Minimalism meets Journalistic Gravitas … 暖石灰底比纯白更柔」。

| 维度 | 评估 |
|---|---|
| 视觉风格关键词 | 格式而非风格；样品风格跨度大（暗金节日风 / 玻璃质感 / 极简编辑风） |
| 色彩体系 | 令牌化，含 `on-*`/`*-container` 语义配对（totality-festival 即 Material 式语义组） |
| 字体与排版 | 令牌组覆盖族/号/重/行高/字距/特性/可变轴 |
| 间距/圆角/阴影 | `spacing`、`rounded`；Elevation & Depth 是独立散文段 |
| 组件风格 | `components.*` 令牌可引用其他令牌 |
| 布局方式 | 由文件描述，规范不强加 |
| 图标与插画 | 不涉及 |
| 动效与交互 | 不涉及（可在 Do's and Don'ts 里写） |
| 暗色模式与响应式 | 无强制约定；靠颜色令牌命名表达 |
| 无障碍 | **内建 WCAG 对比度门禁** |
| 技术栈与复用性 | Node CLI，与我们的 `pnpm run` 门禁天然契合 |
| 许可证 | Apache-2.0（可安全采用） |
| 维护活跃度 | 27,971★，2026-09-14 推送 |
| 文档与示例 | 规范 + 3 个完整样品 + CONTRIBUTING + PHILOSOPHY |
| 与本项目的匹配点 | 给「视觉身份」一个可 lint、可 diff、可门禁的家；对比度检查正对「状态色必须可读」 |
| 冲突点 | **文件名冲突**：它的规范叫 `DESIGN.md`，本仓库 `DESIGN.md` 已是产品设计文档；且本仓库文档规则为英文 |
| 适配成本 | 低（写一个文件 + 一条 `pnpm run` 命令） |

**结论：采用其格式**（令牌 + 理由 + Do's/Don'ts），落地文件名建议 `docs/visual-identity.md` 以避开 `DESIGN.md`；**不作为视觉风格来源**。

### 5. Leonxlnx/taste-skill

可观察证据：`skills/` 下 13 个 skill（taste-skill、minimalist、brutalist、soft、redesign、image-to-code、brandkit、output、gpt-taste…）；SKILL.md 定义**两个视觉原型**：`Swiss Industrial Print`（高对比浅色/新闻纸底、巨型无衬线、可见结构分隔线、激进非对称留白、出血数字、主红作强调）与 `Tactical Telemetry & CRT Terminal`（仅暗色、高密度表格、等宽主导、ASCII 括号与准星等框线、磷光/扫描线/低位深）；硬规则「**Pick ONE per project and commit to it. Do not alternate or mix both modes within the same interface.**」；`# ANTI-GENERIC RULES` 禁令含随机漂浮图标、通用渐变、无意义色块、拼贴布局、假 mini-UI、廉价霓虹、模板化品牌板、**没有灵魂的 SaaS 仪表盘**，收尾一句「Make the design quieter, sharper, and more intentional.」；可调旋钮 `DESIGN_VARIANCE` / `MOTION_INTENSITY` / `VISUAL_DENSITY`；示例 `floria-*.webp` 是暗色编辑风营销页（近黑底、巨型白字、斜体衬线点缀、编号流程、大圆角图卡）。

| 维度 | 评估 |
|---|---|
| 视觉风格关键词 | 反-slop、克制、结构主义；两个命名原型 |
| 色彩体系 | 原型级约束（浅色高对比 + 单一红；或仅暗色 + 信号色），非 token 表 |
| 字体与排版 | 强调巨型无衬线 / 等宽主导，含宏观与微观排版分工 |
| 间距/圆角/阴影 | 强调可见结构线与非对称留白；不规定数值 |
| 组件风格 | 不提供组件，提供判据 |
| 布局方式 | 网格 + 出血元素 + 编号序列 |
| 图标与插画 | 明确反对随机图标与装饰性插画 |
| 动效与交互 | `MOTION_INTENSITY` 旋钮；示例页偏 scroll/magnetic 重动效 |
| 暗色模式与响应式 | 两个原型一暗一亮，规则要求二选一 |
| 无障碍 | 未作为重点（对比度不在其范围内） |
| 技术栈与复用性 | 仅提示词与规则，无代码可复用 |
| 许可证 | MIT |
| 维护活跃度 | 87,931★，2026-09-16 推送（最活跃） |
| 文档与示例 | README + 13 个 SKILL.md + research/ + examples/ |
| 与本项目的匹配点 | ①两个原型正对「控制台/表格」这一界面类型；②反-slop 清单可直接当「不许做」的判据；③三个旋钮可落成项目硬约束（低动效、高密度、低实验度） |
| 冲突点 | CRT 演出（扫描线/磷光）长期使用会疲劳且显廉价；规则禁止混用原型，需要明确「模块分区 ≠ 混用」的边界；示例是营销页而非控制台 |
| 适配成本 | 低（取规则与原型方向，不取代码） |

**结论：可作为约束与判据来源** —— 取「Swiss Industrial Print」的结构规则与反-slop 禁令；CRT 原型只取「等宽 + 高密度」，不取演出。

| 图标与插画 | 具象植物纹样与流水纹（**不可照搬素材**） |
| 动效与交互 | 无 |
| 暗色模式与响应式 | 无 |
| 无障碍 | 不适用 |
| 技术栈与复用性 | 只是一个图鉴网站，无代码可复用 |
| 许可证 | 未标注（网站内容不可假定可复用） |
| 维护活跃度 | 未知（页面存在且可访问；无仓库可查） |
| 文档与示例 | 每风格一页 + 配图 + 关键词，作为词汇表够用 |
| 与本项目的匹配点 | ①与 flexoki 的纸墨中性底同源；②「平面化」正是我们需要的「无渐变、平面分层」；③「金银色」可降级为「金属暖只出现在中性阶里（纸张温度），不进彩色强调」；④「连续构图」可降级为「重复细分割线 / 编号序列」 |
| 冲突点 | 华丽装饰与「工具应当安静」冲突；金箔纹理在 100% 缩放下会变成噪声；具象纹样容易俗 |
| 适配成本 | 中（需要把艺术语言翻译成克制的 UI 语言，做过头就廉价） |

**结论：只作审美词汇与母题来源**（平面化、中性阶里的纸墨温度、连续构图 → 重复分割），**不作界面范式，不采用任何素材**。注意：「金银色」不得转译为彩色强调 —— 第 3 条已确认强调色由系统决定，暖色只保留在中性底里。

## 组合判断

七项分属**不同层次**，因此不存在「只能选一个」的互斥：

| 层次 | 参考项 | 在本项目中的角色 |
|---|---|---|
| 色彩基座 | flexoki | 唯一可直接采用的完整系统 |
| 格式与门禁 | google-labs-code/design.md | 承载令牌与理由，附 WCAG 对比度门禁 |
| 判据与约束 | taste-skill | 反-slop 清单 + 原型纪律 + 三个旋钮 |
| 审美词汇 | rinpa（visualstyles 图鉴） | 平面化、纸墨温度（只在中性阶）、连续构图母题 |
| 流程 | huashu-design、ui-design-agent-kit、ai-website-cloner-template | 三方向取稿、验收证据、参考驱动实现与组件基线 |

**唯一真正互斥的是风格原型**：taste-skill 的 Swiss Industrial Print 与 CRT Telemetry。按其硬规则不得在同一界面混用 —— 本项目的处理方式是**同一原型下的密度分区**（窗口壳层、列表、表单统一走 Swiss 结构规则；只有日志、进度、路径清单、原始数据区采用等宽 + 高对比的「仪表面」处理），而不是两套皮肤切换。

**会产生冲突的混搭**（明确禁止）：webfont 展示字体（Syne/Manrope/DM Mono 与 CJK 系统字混排）；霓虹 lime/coral；金箔纹理与具象植物纹样；CRT 扫描线与磷光；明暗两套不等价；一个画面出现两个强调色；把系统强调色当细线色直接铺在低对比底上（已实测不合格）；文档页做营销式编辑排版（第 8 条已禁止）。

## 推荐方案

方向仍是一个：**墨与纸**，但按已确认约束收紧为「中性优先 + 系统强调色 + 双模式同源 + 键盘优先」。原先写的「单一**暖**强调色」已被第 3 条答案否决，改为「单一**系统派生的**强调色」。

### 方案 A（主推，已按答案收紧）墨与纸 · Ink & Paper

- **关键词**：纸/墨中性底、系统强调色、细线结构、平面无渐变、安静而精确、键盘优先。
- **色彩方向**：flexoki 为中性基座 —— 亮：`#FFFCF0` 纸 + `#100F0F` 墨；暗：`#1C1B1A` 底 + `#F2F0E5` 字（两套实测均 ≥15:1）。**强调色取系统强调色，但经对比度修正层过滤**：仅用于填充块；对比不足时回退到同色相的 flexoki 阶（见下方「对比度修正层」）。状态色仍固定 6 个，与 [ui.md](ui.md#row-states) 的徽标 1:1，新增状态必须同时新增徽标与对比度实测。
- **双模式**：亮/暗两套**同时**定义、同时审查；Mica 是合成底，面板底色必须自绘不透明层，不得直接坐在 Mica 上算对比度。
- **字体方向**：全系统字体 —— 拉丁 `Segoe UI Variable`，中文 `Microsoft YaHei UI`，等宽 `Cascadia Mono` → `Consolas`；**正文 14px 基线**，版本号、路径、日志、字节数用等宽 + tabular；接受系统缩放放大布局，不做「仅字体放大」的特殊处理。
- **布局与密度**：8px 栅格；1px 细分割线替代卡片投影；圆角小（≤6px，浮层 8px）；阴影只用于浮层；行高随 14px 正文重排（列表 36px / 表格 32px / 路径清单 24px）；**单窗口单列骨架**（第 6 条确认不需多面板/多窗口），侧栏可折叠。
- **键盘优先**（第 5 条新增）：焦点环是一等视觉元素（2px 系统强调色外环 + 1px 内环，與底对比不依赖强调色）；提供命令面板（`Ctrl+K`）作全键盘入口；快捷键表进设置页；**密度上限由键盘可达性决定**，任何只能鼠标操作的行内动作都算缺陷。
- **窗口壳层**（第 2 条确认）：无边框标题栏 + Mica，但标题栏与面板均叠加自绘不透明/半透明层，并保证拖拽区、系统按钮与焦点环在三重叠加下依然可辨。
- **参考来源**：flexoki（中性与色阶）+ 系统强调色（主色相）+ taste-skill 的 Swiss Industrial Print（结构线与单一强调）+ rinpa 母题（平面化/暖分割的「温度」只留在纸张中性里，不上彩色）+ 展厅（文档与软件同一语言下的安静排版）。
- **适用场景**：全部界面（应用列表、进度、清理、设置、历史、发现候选），文档与 README 配图同一套语言（第 8 条已禁止编辑化）。
- **风险与约束**：① 中性底偏暖时与蓝色强调易显脏 → 亮色模式下把纸底从纯暖向中性收（向 `#F2F0E5` 靠），实测决定；② Mica + 自绘层叠加下的对比度必须实测而非推算；③ 系统强调色可能低对比（已实测 3.80:1 的反例）→ 必须有修正层与退回路径；④ 焦点环不得依赖强调色，否则低对比主题下全键盘操作会失去可见焦点。

#### 对比度修正层（方向的一部分，不是实现细节）

```
输入：系统强调色 A、当前底色 B、用途 U（填充 / 图形 / 文字）
1. 计算 contrast(A, B)
2. 填充：要求 ≥ 4.5（带白字时另算白字/墨字取优者）
   图形/边框：要求 ≥ 3.0
   文字：要求 ≥ 4.5
3. 不满足时，将 A 映射到 flexoki 同色相阶：
   蓝径 → blue-600 #205EA6（on 纸 6.36:1）/ blue-500 #4385BE（on 暗 4.37:1）
   橙径 → orange-600 #BC5215 / orange-500 #DA702C（on 暗 5.19:1）
4. 仍不满足则发警告（不静默降级）
```

实现上它是一个 token 计算函数，不是手写死值；并在 design.md lint 里对亮/暗两侧各验一次。

### 方案 B（局部）仪表面 · Instrument Surface

- **关键词**：等宽、高对比、tabular、无装饰、只服务数据。
- **色彩方向**：在 A 的中性框架内取最亮/最暗两端做局部反相；信号色只用橙/红/绿表达状态。

**字体方向**：等宽优先；**中文在此区仍回退到雅黑**（Windows 没有可用的 CJK 等宽），因此只对拉丁字符与数字做对齐，不对中文列做等宽假象。

- **布局与密度**：行高 24px（维持原定，因该区以拉丁/数字为主），数字右对齐，列宽固定，允许水平滚动而非换行。
- **参考来源**：taste-skill 的 Tactical Telemetry（仅取等宽与密度，不取扫描线/磷光）。
- **适用场景**：进度日志、`update://progress` 明细、清理路径清单、`history` JSONL 视图、错误堆栈。
- **风险与约束**：不得外溢到设置、历史列表、引导页；一旦整体仪表化就会变成「假终端」； 在该区内也要保住键盘可读（不靠颜色区分错误与普通行）。

### 方案 C（兜底）原生精修 · Native-polished

第 3 条确认「尊重系统强调色」后，C 比原先更接近 A —— 两者的差别只在**中性底的温度**：

- **关键词**：贴近 Windows 11 原生体感、**冷中性**、低个性、几乎不可能难看。
- **色彩方向**：flexoki 中性阶去掉暖偏（或直接用其偏冷的一端），强调色同 A（系统强调色 + 修正层）。
- **字体方向**：同 A（系统字体，正文 14px）。
- **布局与密度**：8px 栅格、8px 圆角、分段控件与列表贴近 Fluent 习惯、Mica/亚克力窗口背景。
- **参考来源**：七项中没有 Windows 原生设计系统的参考 —— C 本质是「无参考的保守基线」，flexoki 只提供中性阶。
- **适用场景**：若 A 在实测（夜间模式、HDR、非 100% 缩放、Mica 叠加）中反复显脏且无法修正时的降级路径。
- **风险与约束**：容易落入 taste-skill 点名的「没有灵魂的 SaaS 仪表盘」；采用前必须穷尽 A 的修正手段（尤其是把纸底向中性收）。

## 明确不建议采用的方案

| 不采用 | 原因 |
|---|---|
| 照搬 ui-design-agent-kit 的 ink + lime/coral 配色 | 无 SPDX 许可（代码/素材/字体都不可复用）；霓虹对比色正属反-slop 禁令 |
| 整体 CRT / Telemetry 化（扫描线、磷光、准星） | 长期使用疲劳，在实用工具上显廉价；且中文无等宽字体，演出无法对齐 |
| 把 rinpa 的装饰语言（金箔、植物纹样）搬进界面 | 华丽装饰与「工具应当安静」冲突；纹理在 100% 缩放下成为噪声 |
| 引入 webfont 展示字体（Syne/Manrope/DM Mono 等） | 与中文 UI 混排不一致；离线打包体积与「纯本机」定位矛盾 |
| 双原型混用（Swiss 与 CRT 同界面切换） | taste-skill 硬规则禁止；会直接毁掉一致性 |
| 克隆式复刻某个网站/应用的界面 | 版权风险；网站范式不匹配桌面工具的密度与键盘操作 |
| 无风格基线直接开写页面 | 结果就是「没有灵魂的 SaaS 仪表盘」—— 这正是本轮要避免的 |

## 已确认约束（2026-09-17 由作者确认，取代原先的待确认清单）

| # | 问题 | 结论 | 对方向的影响 |
|---|---|---|---|
| 1 | 默认模式 | **跟随系统** | 必须明暗成对同源，且**两套都要完整设计**，不能只做一套再加补丁 |
| 2 | 自绘窗口 | **接受**（Mica/亚克力 + 无边框标题栏） | 窗口壳层可进色调，但 Mica 是**带色偏的合成底**，对比度不能按纯色算 |
| 3 | 系统强调色 | **尊重** | 主题色由系统决定，**基座不能再是暖色**（见下方冲突处理） |
| 4 | 中文正文基线 | **14px**；不要求 DPI 下布局不放大 | 接受系统缩放放大布局；密度按 14px 行高重新对齐 |
| 5 | 全键盘操作 + 快捷键表 | **需要** | 焦点环升为设计一等公民；密度须为键盘可达性让路；需要命令面板类入口 |
| 6 | 最小窗口 / 多面板 | **不需要**（不做多面板、不做多窗口） | 单窗口单列骨架成立，侧栏可折叠但不必做面板拖拽 |
| 7 | 导出 / 打印 | **不需要** | 浅色不必为了打印而牺牲屏幕效果 |
| 8 | 文档/展示页更编辑化 | **不允许** | 文档、README 配图与桌面端**同一套语言**，不得出现广告式排版 |

### 答案带来的两个真实冲突

**(a) 尊重系统强调色 ⊥ 暖色基座。** 实测本机强调色 `AccentColor = 0xFFD47800`（按 Windows 的 ABGR 存储 → **`#0078D4`** Windows 蓝），`ColorizationColor = 0xC40078D4`，`ColorPrevalence = 0`。蓝强调 + 暖纸底是最容易显脏的组合，而且系统强调色会随用户改主题变任何色相（本机 Explorer 的 `AccentPalette` 里就同时有青蓝、橙 `#F7630C` 等八色）。

**(b) 实测对比度不足以自动满足无障碍。** 在 Windows 默认蓝 + 本方向候选底上实测：

| 组合 | 对比度 | 判定 |
|---|---|---|
| `#0078D4` 填充 + 白字 | 4.53:1 | 勉强过 AA（正文 4.5） |
| `#0078D4` 作为细线/文字 on 深底 `#1C1B1A` | **3.80:1** | **不合格**（连 AA 都不到） |
| `#0078D4` 作为细线/文字 on 纸底 `#FFFCF0` | 4.41:1 | 差一点，不合格 |
| flexoki blue-600 `#205EA6` on 纸底 | 6.36:1 | 合格（AA） |
| flexoki blue-500 `#4385BE` on 深底 | 4.37:1 | AA 边缘可用（用于图标/边框） |
| flexoki orange-500 `#DA702C` on 深底 | 5.19:1 | 合格（但只作次要强调） |
| 墨 `#100F0F` on 纸 `#FFFCF0` | 18.62:1 | AAA |
| 亮字 `#F2F0E5` on `#1C1B1A` | 15.04:1 | AAA |

**结论：系统强调色可以尊重，但必须带对比度修正层** —— 强调色只用于**填充块**（按钮底、选中行、进度条），不用于细线或小字；当系统强调色与当前底的对比度低于阈值（正文 4.5:1 / 图形 3:1）时，自动改用其同色相的 **flexoki 对应阶**（蓝径 → blue-600/700，橙径 → orange-600/700）。该层必须实现为 token 计算而非硬编码，并用 design.md lint 在明暗两侧各验一次。
